# claude-harness — BRAND

## Name rationale

**claude-harness** is named for exactly what it is: a *harness* for *Claude Code*. In agent
engineering, "harness" = the scaffold around a model — its prompts, skills, hooks, tools, memory,
and rules. The model is fixed; the harness is the part you change. The name says the product in two
words: this is the harness, and the harness is the product.

## Tagline

> **Battle-tested Claude Code scaffold. Same model, 2x output.**

Supporting line: *~1,200 lines of bash and markdown. No daemon. No server. No dependencies beyond
Claude Code.*

## The thesis (the one idea the brand sells)

The same model with a different scaffold produces dramatically different results. The Darwin Godel
Machine went 20% → 50% on SWE-bench by improving the scaffold alone — same weights. Anthropic's own
harness engineering shows 10–22 point gains from scaffold changes. **The harness IS the product.**

## Voice

- Plain, technical, confident. No hype, no emoji as functional UI.
- Show the mechanism (what each hook/skill/rule does and when it fires), not just the claim.
- Honest: measured-not-vibed; a red eval is a blocked release.

## Colors (docs / landing, if/when built)

- Warm black background (`#141312`) — not pure black.
- Amber/machined accent for highlights; serif display + sans body for an editorial, non-AI look.
- Dark mode default.

## Landing-page copy (elevator)

`npx claude-harness` drops a battle-tested Claude Code harness — lifecycle hooks, on-demand skills,
context-aware rules, sub-agents, and a memory system — into any project in seconds. Three tiers
(starter / pro / expert). Same model. Roughly twice the useful output. The harness is the product.
